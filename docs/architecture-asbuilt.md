## 1. 总体架构

```
┌──────────────────────────── 业务层 Game/ （独立边界） ────────────────────────────┐
│  Game/override.cfg ── 覆盖主场景/窗口 ──► Game/Example/ExampleScene.tscn           │
│      ├─ PlayerEntityTemplate-Platformer（+ CollectorComponent，挂 Collector）      │
│      ├─ CollectibleEntityTemplate ×3（CollectibleComponent + ExampleGemPayload）   │
│      └─ HUD/CounterLabel                                                           │
└──────────────────────────────────────────────────────────────────────────────────┘
┌──────────────────────────── 框架层 AutoLoad 单例 ────────────────────────────────┐
│  Global（常量/群组/截图） · Settings（用户配置） · Debug（日志/检查）              │
│  SceneManager（场景栈+转场+暂停） · GlobalInput（输入/全局快捷键）                  │
│  GameState（全局状态/事件总线/玩家管理） · GlobalUI（全局覆盖层/转场蒙版）          │
│  GlobalSonic（音乐/SFX/合成音） · TurnBasedCoordinator（回合制，按需启用）          │
└──────────────────────────────────────────────────────────────────────────────────┘
┌──────────────────────────── 框架层核心机制 ──────────────────────────────────────┐
│  Entity（组件容器/生命周期） ⇄ Component（行为单元，组成式组合）                   │
│  Resources/（Stat、Ability、Upgrade、Payload、StatDependent 资源）                 │
│  Scripts/（Tools 静态工具、Data 数据管线、Mono Luban 服务、Spawner 系列）           │
│  UI/ + addons/Comedot 编辑器工具（ComponentsDock、GameProjectInitializer）        │
└──────────────────────────────────────────────────────────────────────────────────┘
```

**分层原则**：框架层无游戏业务；游戏定制只能走 `Game/` 或"新组件"路径（复用优先，禁止在实体脚本中堆积玩法逻辑）。

## 2. 游戏循环与场景流转

### 2.1 场景状态机

```
[启动] project.godot main_scene → IOLogoScene.tscn (LogoSceneIO.gd)
          │  SceneManager.transitionToScene(GameFrame, pause=false)
          ▼
GameFrame.tscn（主菜单：Logo + MainMenuButtons + UINavigationContainer）
          │  MainMenuButtons → GameState.startMainScene()  （Settings.mainGameScenePath）
          ▼
Settings.mainGameScenePath（框架默认取 run/main_scene；Game 层由 override.cfg 指向 ExampleScene）
          │
          ▼  gameplay ── pause（GlobalInput → SceneManager.togglePause）
```

### 2.2 场景管理（`SceneManager.gd`）

- **栈式导航**：`sceneStack: PackedStringArray`（尾部=顶），`pushSceneToStack` / `popSceneFromStack` / `pushCurrentSceneAndTransition`。
- **转场**：`transitionToScene(next, pause, unpause, animate)` — 防重入（`ongoingTransitionScene` 守卫）→ 暂停 → `GlobalUI.fadeInTintRect` 淡入蒙版 → `change_scene_to_packed` → 短暂喘息 → 淡出。失败回滚暂停状态。
- **暂停**：`setPause/togglePause`，经 `NOTIFICATION_PAUSED/UNPAUSED` 广播 `will/didSetPause`；`GlobalUI.showPauseVisuals` 驱动 PauseOverlay。
- 信号契约：`will/didTransitionToScene`、`will/didPushScene`、`will/didPopScene`、`will/didSetPause`。

### 2.3 启动顺序（fork 实况）

1. AutoLoad 按 `project.godot` 顺序实例化：**Global → Settings → Debug → SceneManager → GlobalInput → GameState → GlobalUI → GlobalSonic → TurnBasedCoordinator**。
2. `Settings` 在 `NOTIFICATION_PARENTED` 阶段即加载 `user://…Settings.cfg` 与项目覆盖（早于 `_ready`）。
3. `GameState._enter_tree()` 调用 `setupGameState()`：加载 `ComedotProjectSettings.globalDataPath` → `GameState.globalData`；实例化 `gameStateNodes` 中列出场景。
4. `GlobalSonic._ready()` 加载音频设置 + 音乐列表，`playInitialMusic.call_deferred()`。
5. LOGO 场景 → GameFrame → 业务主场景。

> ⚠️ **fork 漂移备注**：上游 `docs/best-practices.md` 描述存在 `Scripts/Start.gd`（`Start._enter_tree()→setupGameState()`、`_ready()→startComedot()/applyGlobalFlags()`），**本 fork 无该文件**（无 `Scripts/Boot/`）。启动职责实际由各 AutoLoad 自行完成；`Debug.performFrameworkChecks()` 依赖 `Global.hasStartScript` 属上游假设，本 fork 中相关启动提示会以警告形式出现。新项目脚本骨架由 `addons/Comedot/GameProjectInitializer.gd` 生成（`Scripts/Boot/*Start.gd`），本仓未走该路径。

## 3. ECS/组合式架构（核心）

### 3.1 模型

- **Entity**：任意 Godot 节点挂 `Entities/Entity.gd`（或其子类）；本质是组件容器（`components: Dictionary[StringName, Component]`），挂 `entities` 群组。游戏层极少新建实体脚本。
- **Component**：任意节点挂 `Components/Component.gd` 子类；`class_name` + 场景配对（`*.gd` + `*.tscn` 一一对应，抽象基类 `*ComponentBase.gd` 例外），根节点类型按职责选择（`Node`/`Node2D`/专用节点如 `Timer`/`Area2D`），挂 `components` 群组。
- 根目录 `Components/Component.gd` 提供生命周期、依赖检查（`getRequiredComponents`）、协同组件访问（`coComponents`）、启停（`toggleEnabled`）、删除（`requestDeletion*`）、日志装饰器全套。

### 3.2 组件生命周期（安装/卸载协议）

```
安装：NOTIFICATION_PARENTED → onParented() → Entity.onComponent_parented()
     → Entity.installComponent()（写入 components 字典 / coComponents / 日志）
     → onDidInstall() → _enter_tree()（入群组、checkRequiredComponents）
     → _ready() → [shouldNotifyOnEntityReady] → onEntityDidReady()
删除：NOTIFICATION_PREDELETE/_exit_tree → NOTIFICATION_UNPARENTED → onUnparented()
     → Entity.uninstallComponent() → willRemoveFromEntity 信号 → onWillUninstall()
```

- `Component` 通过 `NOTIFICATION_PARENTED/UNPARENTED` 转发给父 `Entity`（绕过 Godot 缺少"子节点增删回调"的限制）。
- `installComponent` 支持运行时热增删（`ComponentSwapperComponent`、`InjectorComponent`、`transferComponents` 等实现动态换装/注入）。

### 3.3 组件依赖与协同

- 组件间通过 `getCoComponent(Type)` / `coComponents.Type`（按 `class_name` 键）访问兄弟组件；`findSubclasses` 语义允许 `ShieldedHealthComponent` 顶替 `HealthComponent`。
- 典型子系统链路：
  - 战斗：`GunComponent/BulletlessGunComponent → DamageComponent → DamageReceivingComponent → HealthComponent/shielded → KnockbackOnHit/Invulnerability/DamageVisual`
  - 收集：`CollectibleComponent(payload) ⇄ CollectorComponent → CollectibleStatComponent/DropOnDeath`
  - 交互：`InteractionComponent ⇄ InteractionControlComponent/InteractionMouseControlComponent`（含冷却/代价/模态变体）
  - 能力：`Ability(Resource) + AbilityComponent + AbilityControlComponent + AbilityTargeting* + AbilityButton`
  - 网格/回合：`TileBasedPosition/Control/Movement* + TurnBasedComponent + TurnBasedCoordinator`

## 4. 显式系统逆向

### 4.1 输入系统

- `project.godot [input]` 定义输入动作（moveLeft/Right/Up/Down、turn*、aim*、jump、fire、interact、back、pause、ability_ 前缀、debug* 等），键鼠+手柄双绑定。
- `GlobalInput.Actions` 常量表 + `allActions` 反射缓存；`_unhandled_input/_unhandled_key_input` 处理全局快捷键（暂停、窗口、存档、截图、debug）。
- `InputComponent`（组件侧）订阅动作 → 控制组件（`Platformer/Overhead/Asteroids/Scroller/TileBased/TurnBased` 各控制组件）消费。
- `InputMap` 变量由能力/自定义 UI 支持：`ability_` 前缀动态生成，`UI/InputActionsList` 允许玩家改键并回写 `Settings`。

### 4.2 数据与配置管线（Luban）

```
Excel（_ConfigTables/Excel/Datas/*.xlsx + Defines/*.xml + luban.conf）
   │  gen_code_framework.bat / gen_code_client.bat（Luban.dll, cs-bin + json + bin）
   ▼
C# AutoGen（Scripts/Mono/Luban/Configs/AutoGen/*.cs，Y0Studio.Config 命名空间）
   │  + 运行时 .bytes（Assets/Configs/GameConfigs） + JSON 预览（_ConfigTables/Configs/Json）
   ▼
LubanConfigService.cs（C# Godot 节点：LoadConfigs/GetRecord/GetRecords/GetSingleton/Validate…）
   ▼
Tb.gd（GDScript 门面，常量 MethodName，避免手写 C# 方法名）
   ▼
LubanLoader.gd（行→运行时对象 转换工具：loadAll/loadFirst/filter/loadGrouped）
   ▼
LubanConfigNameGenerator.gd（编辑器脚本：生成 TbCfg.gd 表名常量 / TbField.gd 字段常量）
```

- 模式：`map`（GetRecord/GetValue）、`list`（GetRecords）、`one`（GetSingleton）。
- 本仓框架层 `_ConfigTables/Excel` 仅含演示样例（`examples_tb*`：basic/list/singleton/advance）；业务表源在 `Game/_ConfigTables`（业务仓中）。
- ⚠️ `gen_code_client.bat/gen_code.bat` 仍指向 `Game/Cd_ProjectZero/...` 输出路径（历史残留，业务已迁出）；框架演示生成走 `gen_code_framework.bat`。

### 4.3 全局数据与绑定

- `GameState.globalData (GlobalData.tres)`：任意脚本可读写、信号驱动（`didChangeValue/didEraseValue`）；`ApplyGlobalData.gd` 把 key→节点属性做编辑器可见绑定，运行时自动更新。
- `GameState` 同时是**全局事件总线**：`statUpdated / gameDidOver / gameWillRestart / playersChanged / playerAdded/Ready/Removed`。
- 共享 RNG（`GameState.randomNumberGenerator`）保证确定性随机流，支持种子回放。

### 4.4 存档

- `GameState.saveGame/loadGame()`：**实验性**（注释明言 TODO："不保存所有节点状态"）—— `PackedScene.pack(current_scene)` 存 `user://<project>SavedState.scn`。`Settings.saveFilePath`。
- 玩家偏好：`Settings` 动态属性写 `user://…Settings.cfg`（ConfigFile）。

### 4.5 音频

- `GlobalSonic`：`PROCESS_MODE_ALWAYS`；从 `musicFolder`（默认 `res://Assets/Music`）扫描 mp3 建播放列表，随机/顺序/洗牌；`createAudioPlayer` 一次性 SFX（数量上限=10）与 `createAudioPlayerPool` 池化；`beep()` 合成音（`AudioStreamGenerator`）。
- 音量经 `Settings` 的 `musicVolume/sfxVolume` 持久化，总线 `Master/SFX/Music`。

### 4.6 UI 与全局覆盖层

- `GlobalUI`（`PROCESS_MODE_ALWAYS`）：转场淡入淡出蒙版（SceneManager 依赖）、暂停视觉、临时 Label、窗口尺寸管理。
- `UI/` 控件栈：Stat 类（`StatBar/StatPips/StatUI/StatsList`）、行为/能力（`AbilityButton/AbilityButtonsList`）、背包（`InventoryItemUI/InventoryList`）、升级（`UpgradeChoiceUI/UpgradeUI/UpgradeChoicesList`）、菜单（`MainMenuButtons/OptionsUI`）、模态（`ModalUI/PauseOverlay`）、输入改键（`InputMapUI/InputActionsList`）、图表（`Chart/ChartWindow`）。
- UI 事件：`UINavigationContainer` 手柄导航 + `GlobalInput.Actions`；焦点管理（`SetInitialFocus`）。
- `GlobalInput.generateInputEvent()` 支持脚本/自动化注入伪输入（godot-mcp `simulate_input_sequence` 同源）。

### 4.7 回合制子系统（按需）

- `TurnBasedCoordinator`（AutoLoad，`ComedotProjectSettings.isTurnBasedGame=false` 时被移除）：TimedStateMachine 驱动 **Begin→Execute→End** 三阶段，每阶段顺序遍历 `TurnBasedEntity`（实体→组件级联），节流延时 `delayBetweenEntities/delayBetweenStates`。
- `Entities/TurnBased/`：TurnBasedEntity/PlayerEntity；组件：`TurnBasedComponent/Counter/StateUI/TileBased*/Animation/Gravity`。
- 测试：`Tests/TurnBased/TurnBasedTest.tscn`。

### 4.8 网络

- **无网络同步层**。无 ENet/WebSocket 游戏逻辑；唯一网络相关是编辑器辅助 `addons/godot_mcp/websocket_server.gd`（MCP 插件链路）。`GameState` 注释提及多人场景需自行处理死亡判定。

### 4.9 资源管线（非配置类）

- 静态资源以 `res://` 预加载/懒加载：`SceneManager.getScenePathFromClass`（按 `class_name` 推导场景路径约定）、`instantiateSceneFromPath/loadSceneAndAddInstance`。
- 2D Tiles：`TileSet` + `TileMapLayerWithCellData/TileMapCellData`（运行时格数据）、`Global.TileMapCustomData` 约定键（isWalkable/isBlocked/isOpaque/isOccupied/isDestructible…）。
- 动画：`AnimationComponentBase` + 各模式动画组件（Platformer/Overhead/TileBased）；`Scripts/Visual/Animations.gd` 补间工具；`GlobalSonic` 内的较独立。
- 字体/主题：`Assets/Themes/Comedot Default.tres`、`PixelOperator8.ttf`，像素风格全局无抗锯齿。
- Shader/材质：`Assets/Shaders`、`Assets/Materials`（2D，少量）。

### 4.10 生成/刷怪管线

- `Scripts/Gameplay/Spawner*.gd`（Spawner/SpawnerList/Random/Stack/SequenceBase）+ `Scenes/Gameplay/SpawnArea/SpawnPoint/SpawnEdge/SpawnTimer/SpawnWaveTrigger/SpawnLocationTrigger/OnScreenTrigger/PopulateArea`——区域触发、波次、屏幕内外、随机替换（`ReplaceWithRandomScene`）等。

## 5. 模块依赖图（运行时关键边）

```
SceneManager → GlobalUI（转场蒙版）、Debug、NodeTools
GameState    → ComedotProjectSettings、SceneManager、GlobalData、Entity

GlobalSonic  → Settings、FileSystemTools

Tb/LubanLoader → LubanConfigService（C# Node）
LubanConfigService → Y0Studio.Config（AutoGen C#）+ .bytes 文件
UI/*         → GameState（globalData/stats）、GlobalInput、Resources/*
```

## 6. 工程化设施

- **编辑器插件**：`addons/Comedot/`（ComponentsDock 拖放、ComedotProjectSettings 资源、GameProjectInitializer 新项目骨架、脚本模板）；`addons/godot_mcp/`（MCP 服务器插件，`websocket_server.gd`，启用 `enabled=PackedStringArray(...)`）。
- **自动化回归**：`.mcp.json` 注册 `godot-mcp`（stdio）；`docs/godot-mcp-automation.md` 定义安全分级命令集；`Game/Example` 输出标记作为最小回归链路（run_specific_scene → simulate_input_sequence → get_debug_output）。
- **编译治理**：`Comedot.csproj` 显式 `Compile Remove Game/**/*.cs、Temporary/**、Lab/**`——业务/临时 C# 不进入框架编译。
- **Git 结构**：框架仓（develop/master/test-merge/up_stream）；`Game/` 独立业务边界（gitignore + AGENTS.override）；历史业务仓独立存放并为 fork 提供上游合并通道。

## 7. 风险与已知问题（as-built 实测）

| 项 | 说明 | 级别 |
|---|---|---|
| `Start.gd` 缺失 | 与上游启动协议文档漂移；`Debug.performFrameworkChecks` 的 hasStartScript 检查在本 fork 恒不满足 | 中（仅启动校验提示，不影响功能） |
| 存档实验性 | `saveGame/loadGame` 明确 TODO/限制（不保存全部节点状态）；快照含截图调试副作用 | 高（依赖时需重写） |
| Luban 生成脚本残留 | `gen_code_client.bat/gen_code.bat` 指向已迁出的 `Game/Cd_ProjectZero` 路径 | 低（框架生成走 gen_code_framework） |
| 配置无热更 | `GetConfigNames` 每次调用排序小表，无缓存层；大表需注意遍历性能 | 低 |
| `Temporary/Lab` 隔离 | gitignore + 编译排除双保险；若其中文件阻断解析需人工移除（AGENTS 约定） | 信息 |
| 无网络/无服务端 | 纯单机客户端架构；多人需自建 | 信息 |
